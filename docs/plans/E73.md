# E73 -- Scheduling boundary: shared_paths lease keys, --dag export, single_node refusal, contract lint (ADR-0087)

Back-link: [docs/plan.md](../plan.md) (master index). Sibling epics: [plans/](.)

fidelity: executable

Implements ADR-0087, the kazi half of the concurrency layering: kazi plans
(nodes, edges, per-node render) and exports the fleet DAG as data; a fleet
dispatcher schedules one goal per container with fleet and partitions off
via a `single_node` contract flag; the cap lives only in the dispatcher.
Adds `[scope].shared_paths` as fleet-level hotspot lease keys excluded
symmetrically from partition surveys and fleet overlap, and
`[scope].contract` rendered into child nodes with lint. The parent goal
that converges on compile-against-contract is HELD by the ADR and is not
planned here. The dispatcher half (import the DAG into Jobs, honor
`shared_paths` as Attempt-scoped leases, render on the host at the pinned
task sha) is tracked in the fleet repo, blocked on ADR-0087 merging.

Code anchors verified on origin/main at write time (2026-09-05):
`Kazi.Partition.partition/3` (lib/kazi/partition.ex:119-139) surveys ONE
blast radius per goal from the graph/repo-map source (`survey_paths/3`,
:170-176) and groups by `group_overlapping/1` -> `overlaps_cluster?/2` ->
`sets_intersect?/2` (:206-228, the union-find); it never reads
`[scope].write_paths` -- a bare `Kazi.Goal` contributes only its id
(`normalize_goal/1`, :283-291). `Kazi.Fleet` (lib/kazi/fleet.ex:350-370)
is the only overlap test that reads `write_paths` (else `paths`), by
string prefix; E72 T72.1 changes that to expanded globs. `:fleet_concurrency`
is a counting semaphore in `Kazi.Fleet.Execution` (lib/kazi/fleet/
execution.ex:144-172, :459-500). Leases today are PARTITION-scoped:
`Kazi.Coordination.PartitionLease.lease_key/1` (lib/kazi/coordination/
partition_lease.ex:64) keys one lease per partition, acquired on start and
released on terminal by the scheduler (lib/kazi/scheduler.ex:249) -- there
is NO per-file lease around the integration step yet; T73.3 adds one.
`Kazi.Scheduler.Integration.integrate/2` (lib/kazi/scheduler/
integration.ex:167, :207) is where that lease wraps. `[scope]` fields load
in `Kazi.Goal.Loader` (lib/kazi/goal/loader.ex:762-769; field table :67).
`kazi plan render` (lib/kazi/cli.ex:1363-1371) takes a ROADMAP file
(ADR-0056), not a goal-set: `--dag` therefore takes a fleet dir or manifest
(the same source as `apply --fleet`, cli.ex:613, loaded by
`Kazi.Fleet.load/1`, fleet.ex:77) and is a new subcommand form, not a flag
on the roadmap render.

Acceptance: every task's `acc:` green; docs land with the code (ADR-0034);
a fleet fixture of two goals that both touch `mix.exs` (declared shared)
stays two partitions and its export names `mix.exs` as one lease key;

around the integration step" is true in the interactive adapter after
T73.3, not before -- the epic does not claim it earlier.

## Notes

- ADR-0087 decision 4 cites `partition.ex:206-228` as "the blast radius
  `Kazi.Partition` feeds its union-find"; verified. The ADR's context is
  right that the survey is impact-derived, not `write_paths`-derived, so an
  undeclared-but-impacted hotspot still merges partitions -- T73.2 excludes
  only the declared effective set, by design.
- ADR-0087 decision 4 describes the interactive lease as "held only around
  the integration step". On main the only lease is partition-scoped
  (`PartitionLease`, held start-to-terminal); no integration-step lease
  exists. T73.3 creates it; until it lands, the interactive adapter also
  serializes at partition grain for shared keys.
- `kazi plan render` today renders a ROADMAP file (ADR-0056/0082). The ADR
  names `kazi plan render --dag` as the export surface; T73.4 implements it
  as a sibling form taking the fleet source, so the roadmap render grammar
  is untouched.
- The kazi skill source (SKILL.md/AUTHORING.md) is not in this repo's tree
  at write time; T73.7 must find where the installed copy is embedded from
  before editing.
- Scheduler side: the sibling scheduler repo amended its fleet-daemon row
  to consume T73.4's `--dag` export and the `single_node` contract flag,
  and treats `shared_paths` as an additive lease-key source beside its own
  write-set overlap. Its acceptance for two goals sharing a hotspot reads
  "never run concurrently while both hold the key", Attempt-scoped in v1;
  phase-scoped early release is a follow-up on that side needing a daemon
  wire message. Nothing there changes the kazi-side tasks above.
