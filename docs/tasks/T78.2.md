## T78.2: Distinguish mutation detection from checker failure

### Objective

A reviewer can distinguish a detected behavioral fault from an unrunnable
checker. The acceptance audit cannot become stronger when results disappear.

### Scope

- `lib/kazi/audit/predicate_sensitivity.ex`
- `lib/kazi/audit.ex`
- `lib/kazi/read_model/predicate_audit.ex`
- `test/kazi/audit/predicate_sensitivity_test.exs`
- `test/kazi/audit_test.exs`
- `test/kazi/read_model/predicate_audit_test.exs`

Out of scope: mutation generation, automatic dispatch, provider credentials,
changing the meaning of convergence, or treating old records as newly certified.

### Acceptance criteria

Select explicitly targeted predicate IDs. Baseline pass plus mutated fail counts
as detected. Mutated pass counts as survived. Missing/error/unknown counts as
inconclusive. Untargeted guards are excluded. Define eligible as the targeted
baseline-passing set; detected + survived + inconclusive equals eligible.
Sensitivity is detected / eligible, null when eligible is zero, and carries
coverage so inconclusive cases never imply assurance. Invalid/nonpassing baseline
is diagnosed before scoring and cannot silently shrink the selected target set.

Persist additive counts and target identities. Existing records remain readable
with legacy/unknown coverage. Update tests that currently endorse treating
missing/error as detected. Include explicit pass/fail, empty targets, missing ID,
unknown, unrelated guard and read-model reload.

Genuine red: write the missing-result regression against current scoring and
record its predicted failure. After correction it passes; temporarily restore
non-pass-as-detected and show that same regression fails again.
