## T74.1: Preserve task intent across predicate transitions

### Objective
A real dispatched worker receives the declared task even after its first predicate passes.

### Scope
Modify `lib/kazi/loop.ex`, `lib/kazi/harness/prompt.ex`; create
`test/kazi/loop/task_brief_prompt_test.exs`. Out of scope: authoring schema,
model selection, context default tuning, provider billing, unrelated process rules.

### Acceptance criteria
Create two predicates with distinct sentinel descriptions; put the task brief and
required test path in the first. Capture actual adapter prompts across two
observations: first both fail, then only the second fails. Both prompts contain
the same complete requirements and read/write scope; only failing IDs/evidence
change. Include guard descriptions and exact acceptance command/args. Use existing
redaction before egress. Tier zero removes optional orientation, never intent.
Genuine red: restore ID-only work-item construction, observe the sentinel assertion
fail, restore implementation and record both outputs. Do not weaken the test to
assert only predicate IDs.
