## T80.3: Bind landing evidence to reviewed content

### Objective

Fanisi never reports an accepted landed task merely because a PR exists or a
related commit merged. Review and landing describe the same verified content.

### Scope

Execute in the sibling Fanisi repository. Paths below are relative to Fanisi:

- `ledger.go`
- New `landing.go`
- `ledger_test.go`
- New `landing_test.go`
- `docs/evaluation.md`

Out of scope: merging/pushing code, changing GitHub approval policy, counting
multiple repairs as separate tasks, or replacing the existing patch review guard.

### Acceptance criteria

Record task/attempt/repair lineage, repository identity, reviewed base and patch,
candidate identity, review record, target base and merge commit/evidence. Review,
verification and landing are separate facts. Pending/unknown is not landed.

Prove equivalence of the reviewed scoped delta and the landed delta. Rebase or
squash changes commit identity; ancestry alone is insufficient. A conservative
exact comparison may accept unambiguous equivalent content. Intervening changes
or conflicts that prevent proof require fresh verification/review and stay
pending; do not guess equivalence or bulk-hash the whole evolving repository.

Append corrections/revocations; retain prior evidence. A task lineage contributes
at most one accepted task. An assisted repair changes the actor classification,
not the denominator. A regression follow-up does not create another task success.

Tests use temporary Git repos and captured synthetic remote metadata: identical
landing, open PR, amended patch after review, rebase/squash equivalent change,
conflicting/intervening change, duplicate import, wrong repository and revocation.
Genuine red: a changed landed implementation must be rejected; demonstrate the
test failing when identity comparison is bypassed, then restore the guard.

### Verification

From Fanisi: `go test -run 'Test.*Landing|Test.*Review' -v ./...`

Run `go test -race ./...`, `go vet ./...`, `gofmt -l .` and `git diff --check`.
Report executed cases and the expected failing mutation, not only exit status.

Source/release verification and paid-model certification are separate claims.
